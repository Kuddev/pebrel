# 首次备份上线：草稿提交与可撤回的分项恢复

## Status

Proposed — 本地实现，待维护者审查。

## Context

备份导航此前隐藏。用户确认备份从未正式上线，要求直接实现 HTML 原型的四步引导、
按次选择内容和恢复撤回，不承担旧备份兼容或迁移。

## Evidence

- `nebula_app/src/gpui_shell/settings_pane/backup.rs`：连接检查与完成时提交草稿。
- `nebula_app/src/gpui_shell/settings_pane/backup/operations.rs`：异步操作与恢复生命周期。
- `nebula_app/src/encrypted_backup.rs`：归档白名单、认证解密、设置敏感字段过滤。
- `nebula_app/src/encrypted_backup/recovery.rs`：恢复前保存原始文件及存在状态。
- `nebula_app/src/backup_remote/listing.rs`：协议返回的大小随记录保留，不捏造设备信息。

## Decision

1. 首次上线只接受 `PEBRBAK1` 归档和当前 Pebrel 文件名，不增加旧格式探测或迁移。
   本机配置文件的读取仍沿用配置域既有的身份规则，不改应用其他功能。
2. 四步向导使用独立草稿。连接检查只读取已有目录，成功后才能进入密码步骤。
   修改存储时先检查，再显式提交配置及系统凭据；取消不落盘。
3. 内容选择在成功备份后持久化；首次推荐选择只在 UI 的推荐函数定义。
   加密口令使用进程内 `Zeroizing` 缓存，输入控件在完成操作后清空，不保存到配置。
4. 恢复先认证整个归档，列出真实类别，再只覆盖勾选项。覆盖前把目标的原始字节
   及不存在状态写入本机加密恢复点。撤回可以删除恢复时新建的文件。
5. 恢复点不是可交换的普通备份；撤回句柄约束本次目标集合，不扫描历史恢复点或迁移
   旧备份。句柄及其口令由设置页拥有；操作失败时留下恢复点文件供故障调查。
6. 抽屉由设置实体拥有，使用组件库的焦点陷阱与设置页既有 deferred overlay 模式。
   不在窗口全局安装 Sheet，避免设置页关闭后残留弹层；异步结果通过弱实体及序号归属。

## Rejected alternatives

- 继续常驻九个开关或省掉向导：不符合批准的原型。
- 边输入边写配置/凭据：取消会改动真实目的地，连接检查也会污染原状态。
- 用普通导出归档作为撤回：普通导出过滤 SSH 偏好，且没有“原文件不存在”的信息，
  撤回会丢原始字节或留下恢复中新建的文件。
- 给未解密的远端记录填入当前设备名或示例大小：会把未知元数据伪装为真实事实。
- 增加旧版归档读取器、版本分派或迁移层：用户明确确认没有已发布备份需要兼容。

## Consequences

网络、加解密和内容统计在后台执行，渲染只消费准备好的状态。所有真实存储错误均反馈到
当前页面/抽屉。目录检查只证明当前读取成功，不把它当成写入权限保证。

设备信息只在本次上传或成功解密后显示；其他加密归档显示类型标签，不额外下载全部归档。
本机恢复点保持加密落盘；撤回入口及口令随设置页释放，不引入跨启动恢复注册表。

## Validation

回归覆盖归档认证、白名单、类别筛选、精确撤回、新建文件删除、协议列表大小，及真实
GPUI 控件的四步前进/返回、密码不一致、连接失败与抽屉取消。运行结果在本次交付说明中列出。

## Supersedes

None。

## Revisit when

备份正式发布后需要变更格式，或产品明确要求跨启动的恢复点管理时，另行定义合同；
不提前构建版本兼容层。操作系统凭据存储能力扩展也由凭据适配层负责。
