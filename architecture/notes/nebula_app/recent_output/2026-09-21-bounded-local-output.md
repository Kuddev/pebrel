# 静态输出快照与本机引用的持久化边界

## Status

供审核的持久化基础；尚未接入命令采集、设置控件或窗口输出恢复。
关联 #160，本阶段不代表完整功能已交付。

## Context

终端显示、输出文件和布局会话的生命周期不同。多个 pane 可以处于同一目录，
因此目录不能作为旧输出归属。直接回放原始 VT 会再次执行控制动作；
把输出及引用放进共享工作区格式，又会让导出携带本机历史。

## Evidence

- [显示快照与校验](../../../../nebula_terminal/src/grid/snapshot.rs)覆盖主屏、Unicode 重排、容量和控制数据拒绝。
- [有界输出存储](../../../../nebula_app/src/recent_output/storage.rs)复用原子文件写入。
- [发布生命周期](../../../../nebula_app/src/recent_output/storage/lifecycle.rs)的回归测试覆盖两代交接、失败重试和发布回调内失效。
- [本机会话引用](../../../../nebula_app/src/session/local_output.rs)验证引用只随自动恢复格式保存，损坏引用不破坏布局恢复。

## Decision

terminal 层仅捕获和恢复主屏的静态显示字段，恢复到历史区，不重放 VT，
不改活终端屏幕或光标。反序列化与恢复先校验结构、容量和控制数据。

app 层以独立 sidecar 保存有界记录，每 pane 最多五条，每条最多 256 KiB。
正常归档最多 16 MiB，两代原子交接最多 32 MiB；超量先裁剪旧记录再生成引用。
精确引用只属于本机自动恢复文档，共享工作区的导入和导出不携带这些引用。

先持久化输出，再发布会话引用，发布成功前保留旧引用可读取的那一代。
发布失败恢复旧归档；成功后才能回收旧代。回调成功意味着会话已经落盘，
即使回调内代次失效，也必须报告真实的持久化结果并保留交接数据。
后续接入者负责通过同一串行边界提交新的 checkpoint；无引用 checkpoint
不能等同清除全部旧历史，显式清除使用独立操作。

## Rejected alternatives

- 回放原始 VT：会重放控制动作，无法保证只恢复显示。
- 按 cwd 匹配：同目录多 pane 无法确定归属。
- 在共享会话中嵌入输出或本机引用：扩大导出范围和载入成本。
- 发布引用前覆盖旧代：中断后旧会话可能引用已丢失的数据。
- 发布成功后仅凭代次变化返回未提交：内存结果会与实际磁盘状态矛盾。

## Consequences

存储和终端边界可各自验证，后续采集及窗口接入复用同一规则。
本阶段不会自动记录命令或恢复终端输出，也不新增用户设置。
调用方须在后台执行磁盘操作，并承担持久化完成后的生命周期收尾。

## Validation

Windows 上实际运行：存储 24 项、会话相关 105 项、启动恢复 1 项通过；
`cargo test --locked -p nebula_terminal --features serde` 的 352 项通过，
包含使用现有打包资产执行的 ConPTY 生命周期测试。
应用测试启用 `gpui-test-support`；仅关闭应用测试目标的调试符号，断言不变。
这些结果验证本阶段边界，不作为尚未接入的窗口输出恢复验收。
