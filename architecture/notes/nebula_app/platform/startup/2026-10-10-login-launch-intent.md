# Login launch intent and silent startup

## Status

Proposed in the fix for [#535](https://github.com/Kuddev/pebrel/issues/535).

## Context

`silent_start` previously hid the first restored GPUI window for every launch.
Login entries and ordinary shortcuts both invoked `--gpui`, so clicking Pebrel
after enabling silent startup could leave the application hidden in the tray.

## Evidence

- [`platform/startup.rs`](../../../../../nebula_app/src/platform/startup.rs) owns
  the tray/capability guard and the Windows Settings login shortcut.
- [`startup/login.rs`](../../../../../nebula_app/src/platform/startup/login.rs)
  renders macOS LaunchAgent and Linux autostart entries.
- [`installer.iss`](../../../../../scripts/installer.iss) separately owns the
  installer login, Start Menu, and desktop shortcuts.
- [`windowing/startup.rs`](../../../../../nebula_app/src/gpui_shell/workspace/windowing/startup.rs)
  selects the first session and its visibility.

## Decision

Login entries explicitly pass `--launched-at-login`. This process-only CLI flag
does not enter terminal launch snapshots or IPC. Manual launches default to
visible even when `silent_start` is enabled. Silent first-window startup still
requires a tray and native window hiding, and applies only to ordinary session
restore. Explicit directories, commands, isolated sessions, update restores,
runtime windows, and later windows retain their visibility contracts.

The platform module owns the common login arguments. Tests keep the CLI parser,
Unix entry renderers, and installer shortcut in agreement. First-window launch
selection is a focused windowing child module; the general constructor receives
the chosen visibility instead of inferring login intent from event receivers.

## Rejected alternatives

- Inferring intent from `launch_at_login` being enabled also hides manual launches.
- Inferring intent from a parent process or environment is platform-specific and
  cannot reliably distinguish Finder, Explorer, terminals, and login services.
- Treating every first window as a login window caused the reported regression.

## Consequences

Existing unmarked login entries must be regenerated by toggling login startup
off and on, or by the installer recreating the selected autostart shortcut.
They launch visibly until then. Startup does not rewrite user login items
implicitly. The marker is an invocation contract, not a security boundary.

## Validation

Regression tests cover ordinary CLI launches, marked login argument parsing,
tray/capability guards, explicit launch/session exclusions, generated entries,
and visibility propagated into an actual GPUI test workspace. Native Windows,
macOS, and Linux login-session activation still require platform acceptance.
Tests render entry content or use temporary fixtures and do not install login items.

## Supersedes

None.

## Revisit when

The login integration uses an OS API that supplies a reliable launch reason, or
a reviewed migration is added for already-installed login entries.
