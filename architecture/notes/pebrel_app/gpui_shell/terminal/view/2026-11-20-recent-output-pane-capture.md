# 逐窗格命令输出采集与本机引用

## Status

本地候选；相关测试、正常产品构建及隔离 CMD 静态恢复验证已执行，尚未提交或推送。

## Context

网格快照和有界输出存储已有共享实现，但尚需将已确认的 shell 命令与具体窗格关联。
本阶段提供采集、静态恢复和不可变引用，不接入完整窗口输出保存队列或设置控件。

## Evidence

- `pebrel_app/src/gpui_shell/terminal/view/completion.rs` 的 `commit_line` 从屏幕和提示符边界确认提交，运行中程序内部输入不能作为新命令。
- `pebrel_app/src/recent_output.rs` 与 `pebrel_terminal/src/grid/snapshot.rs` 已提供容量约束和静态导入；视图不重复实现。
- `pebrel_app/src/gpui_shell/workspace/session_persistence/shutdown_tests.rs` 保护系统拆除期间最后完整工作区，独立实例保存还须遵循更新预约通道。
- 设置入口原有 1999 行，直接加入本阶段规则后为 2020 行；按启动与恢复准入职责提取后为 1993 行，不提高预算、不压缩格式或删测试。

## Decision

- 只在 `commit_line` 确认分支开始采集；Runtime 输入沿用回显屏障及提交前保存的提示符。结束与快照读取主屏，即使备用屏正活动，也不采集其中的输入。
- 恢复只导入显示数据，不执行命令；弱引用、退出状态、首次提交和关闭采集状态共同拒绝过期恢复。
- 按窗口、窗格及内容摘要生成本机引用，先全局淘汰最旧记录再生成引用。分享工作区始终跳过本机引用，手动导入与复制标签不加载输出。
- 在原会话保存器中保留 prepare/complete 代次边界，同时沿用最新系统退出候选选择、取消及更新预约隔离。prepare 返回 I/O 结果，不能把独立实例更新预约失败伪装成无待保存任务。
- 启动与恢复准入规则集中在设置层 `startup.rs`；原目录校验方法原样迁入，调用接口不变，不改变配置格式和依赖方向。

## Rejected alternatives

- 从任意 Enter、键击镜像、cwd 或运行徽章推断提交或归属：会记录程序内部输入或串档。
- 恢复旧分支的完整会话保存器：会丢失关机冻结和独立实例更新预约行为。
- 为本阶段复制已有快照、存储模块或接入完整输出保存队列：重复权威或越过阶段边界。

## Consequences

保留最近五条和既有容量合同；历史显示不能恢复活进程。当前阶段仍不提供完整保存开关 UI 和窗口输出持久化接线，不应宣称完整产品恢复已接通。

## Validation

终端 580 项、设置 111 项、应用相关去重 438 项通过；文件预算 2 项通过，格式与架构检查通过。正常 GPUI 产品构建及两个同目录原生 CMD 的隔离实测通过：各自恢复五条记录、中文可见、互不串档、继续输入不重复导入且不重跑旧命令。实测使用合成存档，仅证明本阶段静态恢复。启动补全组默认并行运行仍有失败，未修改上游亦可复现；候选串行运行 45 项通过，不将其描述为默认并行全绿。
