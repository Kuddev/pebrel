## 设置 Pebrel 的网络代理

打开 **设置 → 网络**，在 **代理方式**中选择：

| 方式 | 作用 |
| --- | --- |
| **不使用代理** | 使用直接连接 |
| **跟随系统** | 使用检测到的系统代理配置 |
| **自定义代理** | 使用自己填写的代理协议与地址 |

选择自定义代理后，填写代理地址并选择协议。例如，本机 SOCKS5 服务监听 `127.0.0.1:1080`时，选择对应协议并填写这个地址。实际端口以自己的代理软件为准。

## 测试当前配置

1. 完成代理方式、协议和地址输入。
2. 点击 **测试网络**。
3. 查看返回的路线、耗时或错误文字。
4. 修改后重新测试，确认使用的是新的配置。

显示网络连接正常，说明本次测试路线可访问测试目标。某个 SSH 账户或 AI 服务仍有问题时，继续在对应连接或工具中测试。

## 让新终端接入系统代理

网络页还有独立的 **系统代理**开关。开启后，**新建终端**的 `HTTP_PROXY` / `HTTPS_PROXY`环境变量会接入系统代理。

开启后新建一个窗格，再启动需要联网的工具；已经运行的 Shell 和 CLI 不会自动得到重新创建的进程环境。

这个开关与上面的网络代理方式分别控制。CLI 也可能使用自己的网络设置，出现问题时同时检查工具配置。

## 为某个 SSH 主机覆盖代理

编辑 SSH 主机，打开 **高级**页，选择跟随全局、不使用或自定义代理。只有某一台服务器需要直连时，修改该主机即可。

带代理认证或跳板的连接，按[代理与跳板](ssh-routing.md)填写。连接规则预览可以帮助确认最终路线。

## 在 WSL 或服务器中访问网络

工具运行在 WSL 或 SSH 服务器时，网络请求从那个环境发出。尤其是 SSH 服务器上的 `127.0.0.1`指服务器自己，不是你的电脑。

先在实际运行工具的环境中检查代理地址和可达性，再启动 CLI。不要把 Windows 上一次成功的测试当作远端服务也已配置完成。

## 常见失败

**连接被拒绝：**检查代理程序是否运行、协议和端口是否匹配。

**超时：**检查当前网络、VPN、代理到目标的路线和防火墙。

**某个工具仍无法联网：**新建终端重试，并检查工具自己的代理、证书或账户设置。

反馈问题时保留协议、脱敏地址和错误文字，移除代理密码和 Token。
