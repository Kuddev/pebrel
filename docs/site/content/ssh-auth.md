## 使用账户密码

编辑主机，在 **基本**页选择 **密码**认证，填写用户名与密码。希望以后自动使用该密码时，勾选保存到系统凭据库的选项，然后保存主机。

Windows 使用凭据管理器，macOS 使用钥匙串；Linux 需要可用且已解锁的系统凭据服务。保存失败时，仍可按连接提示临时输入密码。

编辑已有连接时，密码框留空会保留已保存的密码。需要移除已存凭据时，使用界面提供的清除操作，不要把留空当成删除。

## 使用私钥

1. 编辑主机，将认证方式切换为 **密钥**。
2. 点击 **选择私钥文件**，选取本机私钥。
3. 有多个身份时，按需要添加其他私钥文件。
4. 测试连接；出现私钥口令提示时，输入创建该密钥时设置的口令。

私钥通常与同名 `.pub`公钥文件成对存在。这里选择的是私钥；公钥应预先由服务器管理员配置到对应账户。

没有手动指定密钥时，连接会结合 SSH config 的 `IdentityFile`和常见默认私钥位置查找。使用 agent 的环境中，也需要确认 agent 中确实加载了所需身份。

## 使用自动认证

选择 **自动**，让连接先尝试可用密钥，再按需要使用密码。服务器只允许公钥认证时，仍需提供被服务器认可的密钥，密码不会代替它。

存在多个身份、经常连错账户时，给这个主机显式指定用户名和私钥，比依赖多个默认身份更容易排查。

## 验证码和多轮认证

服务器使用动态验证码或键盘交互认证时，选择 **交互式**。启动连接后，逐项阅读服务器发来的问题，再输入密码、验证码等内容。

验证码有有效期，输入新的验证码；不需要把动态验证码保存到主机库。服务器问题的内容由服务器决定，不一定每次相同。

## 查看主机密钥提示

账户认证前还可能出现服务器指纹确认。账户密码或私钥用于证明“你是谁”，主机指纹用于确认“连到的是哪台服务器”。首次使用或指纹变化时，都应独立核对。

## 认证失败时检查什么

| 提示或现象 | 优先检查 |
| --- | --- |
| 密码认证失败 | 用户名、密码、服务器是否允许密码登录 |
| 私钥无法读取 | 选中的是否为私钥、文件是否存在、当前用户的读取权限 |
| 私钥口令错误 | 是否输入了密钥口令，而不是服务器账户密码 |
| 多个身份均被拒绝 | 为该主机显式选择正确私钥，检查服务器授权 |
| 验证码一直失败 | 选择交互式认证，并检查验证码和设备时间 |
| 无法保存密码 | 系统凭据服务是否可用、是否已解锁 |

换电脑时，主机 CSV 可以携带连接信息，但密码和私钥需要单独配置，见[迁移](migration.md)。
