## 打开冲突文件

Git 合并、拉取或变基后出现冲突时，在版本控制面板的 **合并冲突**区域找到文件，选择 **在三栏合并器中解决**。

编辑器会打开三列：左侧 **当前版本**，中间 **合并结果（可编辑）**，右侧 **传入版本**。

## 合并需要保留的内容

先比较左右两边，然后在中间结果栏整理最终内容。通常需要同时保留双方不同位置的修改，而不是直接选择一整边。

冲突标记形如：

```text
<<<<<<< 当前版本
这一侧的内容
=======
另一侧的内容
>>>>>>> 传入版本
```

保留正确内容后，删除这些标记行。结果中仍有冲突标记时，页面会显示 **仍有冲突标记**，应用按钮不可用。

## 采用一侧的完整版本

确定整个文件应使用一侧内容时，可以点击该侧的箭头按钮：**用当前版本替换合并结果**，或 **用传入版本替换合并结果**。

这会替换中间结果的完整内容，不是只接受光标附近的一小段。操作前留意中间已经手动整理的修改。

Git 变基时，两侧版本的角色容易与直觉不同。以实际文件内容和正在执行的 Git 操作为准，不能只根据“当前”两个字决定保留哪边。

## 应用并暂存

1. 检查中间结果，确认冲突标记已经全部清除。
2. 点击 **应用并暂存**。
3. 等待状态显示 **已写回并暂存**。
4. 返回版本控制面板，检查这个文件不再列为未解决冲突。
5. 运行项目测试或检查命令，然后完成原来的 Git 操作。

“应用并暂存”会保存文件并执行对应的暂存操作，不会自动替你完成整个合并或变基。

在终端运行 `git status`查看下一步提示。如果当前正在变基，按 Git 提示执行 `git rebase --continue`；普通合并则按当前仓库状态完成提交。

## 需要重新读取时

文件被其他工具修改，或冲突状态发生变化时，可以点击 **重新读取冲突阶段**。先复制中间尚未保存的内容，以便比较或恢复。

二进制文件和超出合并器文本大小限制的文件，需要使用相应的外部工具处理。某一侧显示“文件不存在”时，还要决定是否保留该文件；删除类冲突应结合 `git status`提示处理。
