## Pebrel 如何对待 AI 命令行工具

Claude Code、Codex 这类工具本质上是运行在终端里的程序，所以任何 CLI 或 TUI 都能在 Pebrel 里正常使用，不需要先"被支持"。Pebrel 做的是在此之上多走一步：认出你正在运行的是哪一个工具，再给它配上图标、任务状态、通知和对话接续。

这些能力分三层，工具支持到哪一层，你能得到的体验就到哪一层：

| 层级 | 你会得到什么 | 需要你做什么 |
| --- | --- | --- |
| **识别** | Pebrel 认出工具名称，可显示专属图标 | 不需要，直接运行即可 |
| **屏幕识别** | 在识别的基础上，Pebrel 根据终端画面判断工具是在工作，还是在等你确认 | 不需要 |
| **Agent 集成** | 工具自己把"开始、完成、需要你处理"等事件告诉 Pebrel，状态和通知最准确；还能记住会话，用于恢复与分叉 | Claude Code 和 Codex 默认已开启；其他工具在 **设置 → Agents** 里打开一次 |

Agent 集成最准确，但并不是所有工具都提供可用的事件接口。没有集成的工具，依然可以靠屏幕识别获得不错的状态提示，只是在工具改了界面措辞之后，判断可能暂时不准。

## 支持 Agent 集成的工具

**设置 → Agents** 页面里列出的就是下面这 9 个工具，在 Windows、macOS 和 Linux 上都可以使用。Claude Code 和 Codex 默认开启，其余的需要自己打开开关；开启后要退出并重新启动对应的工具才会生效，步骤见[配置 Agent 集成](hooks.md)。

服务器上的工具也可以使用：通过 Pebrel 的 SSH 连接时，会自动为服务器上的 Claude Code、Codex、OpenCode 和 Pi 配置集成。WSL 里则支持 Claude Code 和 Codex。

| 工具 | 启动命令 | 专属图标 | 恢复对话 | 分叉对话 |
| --- | --- | :---: | :---: | :---: |
| Claude Code | `claude` | ✓ | ✓ | ✓ |
| Codex | `codex` | ✓ | ✓ | ✓ |
| OpenCode | `opencode` | ✓ | ✓ | ✓ |
| Cursor Agent | `agent`、`cursor-agent` | — | ✓ | — |
| Kimi Code | `kimi` | ✓ | ✓ | ✓ |
| Pi | `pi` | ✓ | ✓ | ✓ |
| Oh My Pi | `omp` | ✓ | ✓ | ✓ |
| GitHub Copilot | `copilot` | — | ✓ | — |
| Grok | `grok` | ✓ | ✓ | ✓ |

几点说明：

- Cursor Agent 的命令是 `agent`，不是 Cursor 桌面编辑器的 `cursor`。只安装了桌面编辑器时，设置里不会把 Cursor Agent 显示为已安装。
- 没有专属图标的工具会用字体图标代替：Gemini、Cursor Agent 和 GitHub Copilot 各有自己的图案，其余工具显示通用图标。这不影响状态提示。
- "恢复"指重新打开 Pebrel 后接回原来的对话，或在 [AI 会话历史](ai-history.md) 里重新打开某次对话。"分叉"指从已有对话的上下文开出一个新对话，原对话保持不变。两者都要求 Pebrel 已经知道这次对话的会话标识，而这正是 Agent 集成带来的。

## 通过 `npx` 等启动器运行也能识别

Pebrel 不只看命令的第一个词。通过 `node`、`npx`、`bunx`、`uvx`、`pipx` 等启动器运行的工具，以及在 WSL 里运行的工具，同样会被认出。

如果工具没有被认出，先在同一个终端里确认命令能直接运行，再看[配置 Agent 集成](hooks.md)中的排查步骤。

## 名单之外的工具

不在上面名单里的 CLI 或 TUI，仍然可以在 Pebrel 里正常运行，只是没有专属图标、任务状态和对话接续，终端本身的所有功能不受影响。

## 接下来的方向

下面是目前的开发方向，不是发布时间的承诺，具体以各版本的发布说明为准：

- **补齐集成。** 优先为使用广泛、并且官方提供稳定事件接口的工具增加 Agent 集成，让它们从"屏幕识别"升级到最准确的一档。
- **扩大恢复和分叉的范围。** 只在工具的官方命令经过核对之后才会加入。Pebrel 不会按名字猜测命令，以免把内容输入到错误的位置。
- **识别更多工具。** 新工具会根据使用情况和启动方式是否稳定来评估。

希望支持某个工具，可以在项目的 Issue 里说明工具名称、启动命令和官方文档链接，流程见[参与贡献](contributing.md)。

## 常见问题

### 状态没有更新，或图标没有出现

先确认命令在同一个终端里能直接运行，再刷新 **设置 → Agents**。已经启用集成的工具，重启一次工具后再试。工具刚升级过时，重新启动 Pebrel 和工具可以清掉旧的识别状态。

### 在标签上怎么看状态

工作中的标签会显示转动的进度标记。工具停下来等你输入或授权时，标签会改为相应的提示。任务完成时，标签先短暂显示对勾，再变成一个小圆点，提醒你回去查看；正在查看的标签不会显示这个小圆点。详见[使用 AI 命令行工具](ai-start.md)。

### 通知来自哪个窗格

通知会指向发出事件的窗格。多个工具同时运行时，请按窗格上的图标和名称区分，通知方式见[通知](notifications.md)。

### 设置里没有我的工具

**设置 → Agents** 只列出有 Agent 集成的 9 个工具。其他工具没有开关，但仍会被识别，并显示图标和状态提示。

### 恢复或分叉没有出现

先看工具是否在上面"支持 Agent 集成"的表里且有 ✓，再检查集成是否已启用并重启过工具。SSH 标签和自定义 Profile 里不会显示分叉入口，详情见[恢复与分叉 AI 对话](ai-history.md)。
