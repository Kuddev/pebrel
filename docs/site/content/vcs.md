## 查看项目改动

在本地终端进入 Git 仓库，按 **Ctrl+Shift+G**（macOS 为 **⌘⇧G**）打开版本控制面板。面板会显示当前仓库、分支和文件状态。

如果显示的不是当前项目，使用 **回到终端当前目录**；执行外部 Git 命令后，点击刷新按钮重新读取状态。

在 **设置 → 交互 → 侧栏版本控制**中，可以选择 **自动检测**、**仅 Git**或 **仅 SVN**。

## 暂存准备提交的文件

1. 查看 **变更**列表，打开文件检查内容。
2. 对需要提交的文件选择 **暂存**。
3. 在 **已暂存**列表确认本次提交范围。
4. 放错文件时，选择 **取消暂存**将它移回未暂存区域。

确定所有改动都属于同一任务时，可以使用 **全部暂存**。取消暂存只调整提交范围，不会丢失工作区里的文件修改。

## 创建提交

在提交信息框输入简短说明，例如“修正安装指南中的目录示例”，点击 **提交**。成功后刷新状态，已提交的改动会从待提交列表中移除，并出现在历史中。

提交失败时，阅读错误消息。Git 用户身份未设置、提交钩子失败或冲突未解决，都需要先在当前仓库处理，再重试。

## 拉取和推送

使用 **拉取**获取远端更新，使用 **推送**发送本地提交。提交到本地仓库后，仍需推送才能让远端看到它。

远端认证由当前 Git 环境处理；SSH 主机库保存的登录凭据不一定用于 Git。可以在同一终端运行 `git remote -v`检查远端地址。

拉取出现冲突时，转到[解决 Git 冲突](git-conflicts.md)，不要反复点击拉取或直接丢弃文件。

## 阅读历史和分支线路

切换到历史相关视图，查看提交信息及线路。线路显示提交之间的连接关系，便于识别分支和合并。检查某次改动时，先确认仓库路径和当前分支，再查看对应文件。

## 丢弃不需要的修改

对未提交的改动使用 **丢弃改动**，并在确认框核对范围。它会撤销相应文件的本地修改；需要保留的部分应先复制或提交。

“取消暂存”用于暂时不提交，“丢弃改动”用于撤销修改，两者不能互换。

## 使用 SVN

进入 SVN 工作副本后，自动检测模式会切换到相应操作。SVN 使用添加、更新和提交，没有 Git 的暂存区与推送步骤。Windows 上的高级图形操作可交由 TortoiseSVN，见[SVN 工作副本](svn.md)。
