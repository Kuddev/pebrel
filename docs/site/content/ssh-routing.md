## 先确认需要哪种连接方式

直接能访问服务器时，保持直连即可。网络只允许通过代理访问外部地址时，设置代理；服务器位于内部网络、必须经过堡垒机时，设置跳板。

编辑主机并打开 **高级**页，可以分别配置这两部分。

## 使用全局代理

1. 在 **设置 → 网络**填写代理类型、地址、端口及必要的认证信息。
2. 使用网络测试入口检查代理。
3. 编辑 SSH 主机，打开 **高级**页。
4. 将代理策略设为 **跟随全局**，保存并测试连接。

某台主机不需要代理时，把它的代理策略改为 **不使用**；不必关闭所有连接共用的全局代理。

## 为单台主机指定代理

在主机的 **高级**页选择自定义代理，填写 SOCKS5 或 HTTP CONNECT 代理的地址和端口。代理要求认证时，再填写用户名和密码。

代理端口应在 `1–65535`范围内。填写密码时同时填写用户名；编辑后先用 **测试连接**检查，再保存为日常连接。

HTTP CONNECT 代理的认证传输本身不等同于经过 TLS 保护的代理通道。使用不可信网络时，应选择管理员提供的安全接入方式。

## 使用跳板机

假设目标是内部主机 `10.0.0.20`，需要经过 `gateway@bastion.example.com:22`：

1. 为目标主机填写它自己的地址、用户名和认证信息。
2. 在 **高级 → 跳板**中选择 **指定主机**。
3. 选择已有跳板条目，或填写 `gateway@bastion.example.com:22`。
4. 查看 **连接规则预览**，确认路线经过跳板再到目标。
5. 测试连接，按需处理跳板和目标各自的认证提示。

已有 SSH config 的 `ProxyJump`设置时，可以选择 **跟随 SSH config**。需要忽略配置里的跳板时，选择 **不使用**。

跳板账户和目标服务器账户可能不同，请分别填写。把目标密码填给跳板，不会让后续认证自动成功。

## 同时使用代理和跳板

代理作用于连接路线的第一段。例如可以先通过代理连接堡垒机，再由堡垒机访问内部服务器。使用连接规则预览检查第一跳，避免代理指向或跳板地址配置反了。

## 找出失败的是哪一段

先测试代理或堡垒机自身是否可达，再测试目标连接。代理拒绝通常需要检查类型、端口和代理认证；跳板认证失败检查跳板账户；到达跳板后仍超时，检查它到内部目标的网络与防火墙。

服务器指纹校验仍需要按提示完成，代理和跳板不会替代身份校验。
